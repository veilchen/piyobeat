# ぴよビート Web版 — 開発ハンドオフ

ぴよログのテキスト出力をブラウザに貼ると、その場で曲にして、聴いて、共有できる静的Webアプリを作る。
このフォルダには、仕様（この文書）、動くプロトタイプ、合成のテスト用データが入っている。

```
HANDOFF.md                      この文書
prototype_piyobeat.html         動くプロトタイプ（合成データ入り。単体でブラウザで開ける）
synthetic_export_2026-01.txt    ぴよログ テキスト出力の書式を再現した合成データ（実データではない）
```

実データ（ぴよログの月別テキスト出力）は手元にある。リポジトリ内の `private/` に置き、`.gitignore` で必ず除外する。コミット・ログ出力・テストのスナップショットに実データを含めない。テストは合成データで書く。

---

## 1. 最重要要件：デリケートな情報を残さない

育児記録には、子の名前、月齢（＝生年月日）、受診・投薬、家族の睡眠、自由記述の日記が含まれる。以下はすべて必須要件。

### 1-1. 処理はすべてブラウザ内
- 入力テキストをサーバに送らない。バックエンドは作らない。配信は静的ホスティング（GitHub Pages / Cloudflare Pages など）のみ。
- CSPで外部通信を物理的に塞ぐ。最低限：
  `default-src 'self'; connect-src 'none'; img-src 'self' data: blob:; media-src 'self' blob:; script-src 'self'; style-src 'self'; font-src 'self'; form-action 'none'; base-uri 'none'`
  （静的ホストでヘッダを付けられない場合は `<meta http-equiv="Content-Security-Policy">` で。）
- 外部CDN・Webフォント・アナリティクス・エラートラッキングを使わない。フォントを使うなら同梱する。
- 生の入力テキストを localStorage / IndexedDB / sessionStorage に保存しない。タブを閉じたら消える状態にする。保存してよいのはUI設定（テンポ・音階など）だけ。
- console 出力や例外メッセージに入力行を含めない。パース失敗は「何行目が読めなかったか」の件数だけ示す。

### 1-2. パーサは許可リスト方式
必要な項目だけを抜き出し、それ以外は読んだそばから捨てる。

- **使う**：日付、時刻、種別（母乳・ミルク・搾母乳・搾乳・おしっこ・うんち・寝る・起きる・お風呂）、数値（授乳分数・ml）、うんちの量の段階、授乳の最後の側
- **捨てる**：子の名前と月齢の行、各行のメモ欄、日ごとの集計行、日記欄、くすり・病院・予防接種・体温・体重・身長・頭囲・胸囲・吐く・メモ・その他・できた・さんぽ
- **カスタム項目は一律で捨てる**：ぴよログでは記録項目を利用者が自由に追加できる（例：家族の睡眠、気になった出来事）。項目名そのものが個人的な内容になりうるので、上の「使う」にない項目名の行は、名前を見ずにすべて捨てる。読めなかった行として件数に数える必要もない。
- 内部データ（`Event`）に文字列フィールドを持たせない。数値と列挙型だけにする。これで自由記述が後段に漏れる経路がなくなる。

### 1-3. 共有する出力を最小化する
共有手段は2つ。どちらもサーバを経由しない。

1. **音声ファイルの書き出し**：`OfflineAudioContext` でレンダリングして WAV をダウンロード。出力に含まれるのは音だけ。
2. **共有リンク**：譜面を URL の fragment（`#` 以降）にエンコードする。fragment はHTTPリクエストに含まれないため、ホスティング側のログに残らない。
   - 中身は **相対日番号（0始まり）・15分スロット・種別・段階化した量** のみ。絶対日付、月、曜日、名前、月齢、生の分数・mlは入れない。
   - 絶対日付を入れないのは、月齢と組み合わせて生年月日を推定されるのを防ぐため。
   - 任意オプション：時刻を ±1スロットずらす「ゆらぎ」、期間の切り出し。

UI上で、「曲からは記録の時刻パターン（いつ授乳・排泄・睡眠したか）が読み取れる」ことを共有前に明示する。完全な匿名化はできない、という前提を隠さない。

## 2. 入力フォーマット：ぴよログ テキスト出力

月ごとに1ファイル。複数月を連結して貼られても、ファイル複数をドロップされても読めるようにする。

### 2-1. 構造
```
【ぴよログ】2026年1月           ← 月ヘッダ（無視してよい）

----------                      ← 日の区切り
2026/1/10(土)                  ← 日付行  /^(\d{4})\/(\d{1,2})\/(\d{1,2})\(.\)$/
テスト (1か月10日)                ← 子の名前と月齢：破棄（読んだ値をどこにも保持しない）

00:10   おしっこ                 ← 記録行  /^(\d{2}):(\d{2})   (.+)$/
01:15   母乳 左 10分 → 右 12分
...
                                ← 空行
母乳合計　　   左 101分 / 右 81分 ← 集計行：破棄
ミルク合計　   1回 80ml
睡眠合計　　   7時間25分
おしっこ合計   9回
うんち合計　   0回
                                ← 空行
（日記：自由記述が0行以上）      ← 破棄
----------
```
- 記録行の区切りは **半角スペース3つ**。`HH:MM` ＋ 3スペース ＋ 本体 ＋ 3スペース ＋ メモ（空のこともある。末尾に3スペースだけ残ることが多い）。
- 本体 = `parts[0]`、メモ = `parts[1..]`。メモは即座に捨てる。
- 記録行は時刻順。同時刻の行が複数ありうる。
- 日記は集計行のあとに来る。「記録行の正規表現に合わない行」はすべて捨てればよい。
- 複数の子を記録している場合の書式は未確認。名前行が日ごとに複数出るなら、最初の子だけ使うか、子の選択UIを出す（名前は表示しない。「1人目」「2人目」）。

### 2-2. 記録の本体（実データから確認したパターン）

| 本体の例 | 種別 | 取り出す値 |
|---|---|---|
| `母乳 左 10分 → 右 12分` | 母乳 | 左10・右12、**最後は右** |
| `母乳 左 11分 ← 右 10分` | 母乳 | 左11・右10、**最後は左**（右から始めて左で終わり） |
| `母乳 左 1分 / 右 1分` | 母乳 | 左1・右1、順序なし |
| `母乳 左 25分` / `母乳 右 7分` | 母乳 | 片側のみ |
| `母乳 左 8分 → 右 7分 (85ml)` | 母乳 | 末尾の `(Nml)` は量（任意） |
| `母乳 母乳` / `母乳 母乳 (5ml)` | 母乳 | 分数なし（左右とも0として扱う） |
| `ミルク 80ml` | ミルク | 80 |
| `搾母乳 30ml` | 搾母乳（搾った母乳を哺乳瓶であげた記録） | ml |
| `搾乳 30ml` | 搾乳（親が搾った記録。赤ちゃんの摂取ではない） | ml |
| `おしっこ` | おしっこ | — |
| `うんち` / `うんち (多め/やわらかめ/茶色)` | うんち | 括弧内は `/` 区切りの任意の部分集合。下記参照 |
| `寝る` / `寝る ( ! )` | 寝る | — |
| `起きる (3時間45分)` / `起きる ( ! )` | 起きる | 括弧内の時間＝その睡眠の長さ（任意） |
| `お風呂` | お風呂 | — |

矢印の意味は、同じ記録の公式JSONフィード（`last` フィールド）と突き合わせて確認済み：**矢印の先が最後に吸わせた側**。

うんちの括弧内は、量・かたさ・色のうち記録したものだけが並ぶ（`(ちょこっと)`、`(かため/橙)`、`(ふつう/(ふつう))` など）。トークンごとに辞書で判定する：
- 量：`ちょこっと`→minimum、`少なめ`→small、`ふつう`→normal、`多め`→large
- かたさ：`かため`、`ふつう`、`(ふつう)`、`やわらかめ`、`下痢`
- 色：`橙`、`茶色`、`黄色` ほか
- 注意：`ふつう` は量にもかたさにもある。**最初のトークンが量の辞書にあれば量**、それ以外はかたさとして読む。`(ふつう)` の括弧付きはかたさ。使うのは量とかたさ。色は読んだら捨ててよい。
- かたさの対応：`かため`→hard、`ふつう`/`(ふつう)`→normal、`やわらかめ`→soft、`下痢`→diarrhea（公式JSONフィードの `hardness` と同じ値）

`( ! )` は、対になる記録が見つからず睡眠時間を計算できないときの印（利用者に確認済み）。
- `寝る ( ! )`：直前に対応する「起きる」がない。前の「寝る」が閉じていないので、2-3の規則2（前の睡眠の続きとしてつなげる）の対象になる。
- `起きる ( ! )`：対応する「寝る」がなく、長さも分からない。開始時刻を決められないので、区間は作らない。

日の区切りをまたぐ時刻（24:00以降）は出てこない。日付行と時刻から絶対時刻を作る。

### 2-3. 睡眠区間の組み立て
ぴよログの睡眠記録は抜けが多い。公式の可視化に合わせて、次の規則で区間にする。
1. 「寝る」から次の「起きる」までを1区間とする。
2. 間に「起きる」が抜けて「寝る」が続く場合は、最初の「寝る」から次の「起きる」までをつなげる（実例：22:35 寝る → 07:00 寝る → 08:40 起きる は 22:35〜08:40 の1区間）。
3. 「寝る」がなく「起きる (N時間N分)」だけある場合は、長さから開始時刻を逆算する。
4. 14時間を超える区間は記録漏れとみなして捨てる。
5. 日をまたぐ区間は描画時に日ごとに分割する。

## 3. 内部データと共有フォーマット

```ts
type Kind = 'breast' | 'formula' | 'expressed' | 'pump' | 'pee' | 'poop' | 'bath' | 'sleep';
interface Event {
  day: number;        // 入力の最初の日を0とする相対日
  minute: number;     // 0..1439
  kind: Kind;
  left?: number;      // 母乳：分
  right?: number;     // 母乳：分
  last?: 'L' | 'R';
  ml?: number;        // ミルク・搾母乳・搾乳
  amount?: 0|1|2|3;   // うんち：minimum..large（記録なしは未設定）
  hardness?: 0|1|2|3; // うんち：hard, normal, soft, diarrhea（記録なしは未設定）
  len?: number;       // 睡眠：分
}
```
絶対日付は画面表示（「10/5」など）のためだけにメモリ上に保持し、共有リンクには入れない。共有後の画面では「1日目、2日目…」と表示する。

共有リンクの案（v1）：
- 1イベントを数バイトに詰める：相対日（1バイト、最大255日）・15分スロット（0〜95）・種別（3ビット）・段階化した値（3〜4ビット。うんちは4ビット：授乳は合計分数を8段階、ミルクは量を8段階、うんちは量4段階＋かたさ4段階、睡眠は長さを別フィールドでスロット数）
- `CompressionStream('deflate-raw')` で圧縮し、base64url にして `#v1.` の後ろに置く。
- URLの長さの目安：28日分で数KB以内に収める。長すぎる場合は期間を短くするよう案内する。
- 読み込み側はバージョン番号で分岐する。

## 4. 音と譜面（プロトタイプで決めた仕様）

`prototype_piyobeat.html` がそのまま動く参照実装。Web Audio API だけで音を作っている（サンプル音源なし）。

- 1日＝1小節。テンポは「1日あたりの秒数」（3〜20秒、初期値6秒）。3時間＝1拍として BPM を表示。
- 15分グリッドへのスナップ（オン/オフ）。
- 音色と対応：
  - **授乳はすべてメロディ**：母乳・ミルク・搾母乳は同じ音階・同じ音域で鳴らし、飲んだ量が多いほど低い音にする。完全ミルクでも完全母乳でも主旋律が成り立つようにするため（ミルクをベースにすると完ミの人はベースだらけになる、という指摘から変更）。
  - 母乳：木琴風（sine＋4倍音の短い減衰）。合計授乳時間で音程を決める。左のみは左、右のみは右に定位。
  - ミルク：フルート／オカリナ風（sine＋弱い2倍音、遅れてかかるビブラート、息のノイズ）。量で音程と音の長さを決める。
  - 搾母乳：鉄琴（FM合成のベル）。1オクターブ上。量で音程を決める。
  - 搾乳：赤ちゃんの摂取ではなく親の作業なので、メロディにせず「シュッ・ポッ」を4回刻むポンプのリズムにする。
  - ベース：記録に関係なく、3時間ごとにその日のコードの根音（ときどき5度・4度）を弾く自動パート。
  - おしっこ：ハイハット（ノイズ＋ハイパス、ピーク約0.22、減衰0.07秒）。1日10回以上鳴るので、これ以上は上げない。
  - うんち：**量で楽器を変える**（音量差だと聞き分けにくいため）。音量はどれも大きめでそろえる。
    - ちょこっと：リムショット（短い「カッ」）
    - 少なめ：タム（音程感のある「トン」）
    - ふつう：キック（「ドン」）
    - 多め：キック＋クラッシュシンバル（派手な山場）
    - 量の記録なし：キック
  - うんちの**かたさで響きを変える**（どの楽器にも共通の補正）：
    - かため：余韻 ×0.55、音程 ×1.12（短く高い）
    - ふつう／記録なし：補正なし
    - やわらかめ：余韻 ×1.4、音程 ×0.94
    - 下痢：余韻 ×1.5、音程 ×0.9、ノイズを混ぜてざらつかせる
  - 睡眠：寝ている区間だけパッド（三角波×2本のデチューン＋ローパス）。
  - お風呂：高音の上昇アルペジオ。
  - 時報：3時間ごとのウッドブロック。0時は強拍。
- 日が変わるたびにコードが I → vi → IV → V と進む。
- 音階の切り替え：ペンタトニック・琉球音階・都節・リディアン。
- 譜面表示：縦が日、横が0〜24時。睡眠は帯、授乳は丸、排泄は四角。**うんちの四角は量で大きさが変わる**。発音した瞬間に記号が膨らむ。行をタップするとその日から再生。
- 楽器ごとのミュート。オンにした瞬間にその楽器を試聴できる。

スケジューラは `setInterval(40ms)` で 0.2秒先までを `AudioContext.currentTime` 基準で予約する方式。テンポ変更時は現在位置を基準に取り直す。

## 5. 画面の流れ

1. **入力**：テキストエリアに貼り付け、または .txt を複数ドロップ。「データはこの端末の中だけで処理され、どこにも送信されません」と明示。
2. **確認**：読めた期間・件数・種別ごとの件数、読めなかった行の件数を表示。範囲の選択。
3. **演奏**：プロトタイプの画面。
4. **共有**：WAV書き出し／共有リンク作成。共有前に「リンクに含まれるもの・含まれないもの」を一覧で示す。
5. 共有リンクを開いた人は、入力なしで3の画面（相対日表示）から始まる。

スマホで使う前提（ぴよログはスマホアプリなので、貼り付けもスマホから）。iOS Safari は音の開始にタップが必要。

## 7. 技術スタックの提案

- Vite ＋ TypeScript。UIは素のDOMか Preact 程度で十分。
- テストは Vitest。パーサは純粋関数にして、DOMから切り離す。
- 依存パッケージは最小限に。本番バンドルに外部通信をするコードが入っていないことを確認する。
- `private/` を `.gitignore` に入れてから最初のコミットをする。

構成の目安：
```
src/parse/piyolog-text.ts   テキスト → Event[]（許可リスト方式）
src/parse/sleep.ts          睡眠区間の組み立て
src/share/codec.ts          Event[] ⇄ 共有リンク
src/audio/engine.ts         スケジューラ
src/audio/voices.ts         音色
src/audio/render-wav.ts     OfflineAudioContext → WAV
src/ui/score.ts             譜面のcanvas描画
tests/fixtures/             合成データのみ
private/                    実データ（gitignore）
```

## 8. Claude Code に最初に渡す指示（例）

> このフォルダの HANDOFF.md を読んで、ぴよビートのWeb版を作りたい。まず `.gitignore`（`private/` を除外）を作り、Vite＋TypeScriptのプロジェクトを用意して、パーサ（`src/parse/`）とそのテストから始めて。テストは `synthetic_export_2026-01.txt` を使い、実データは `private/` にあるものをローカルでの件数確認にだけ使うこと。音と画面は `prototype_piyobeat.html` の挙動を移植する。プライバシー要件（HANDOFF.md 1章）は全部満たすこと。
