# 共有リンクの符号化

共有リンクは `https://veilchen.github.io/piyobeat/#v2.〜` の形です。`#` 以降（fragment）はブラウザからサーバへ送られないので、ホスティング側のログに残りません。実装は [src/share/codec.ts](../src/share/codec.ts) にあります。

## 全体の流れ

```
パース結果（Event[]）
  → 段階化（Note[]）            src/score/notes.ts
  → バイト列に詰める（v1 / v2）
  → deflate-raw で圧縮          ブラウザ標準の CompressionStream
  → base64url で文字列にする     A–Z a–z 0–9 - _ の64文字。3バイトが4文字になる
  → 先頭に "v2." を付ける
```

開く側は逆の順にたどります。先頭の `v1.` / `v2.` で形式を判別するので、旧形式のリンクも開けます。

### 段階化（両形式共通）

リンクに入るのは、曲を鳴らすのに必要な、粗くした値だけです。

| 項目 | 入れる値 |
|---|---|
| 日 | 範囲の1日目を0とする番号（絶対日付・曜日は入れない） |
| 時刻 | 15分単位のスロット（0〜95） |
| 母乳 | 合計分数を8段階（0〜7）＋どちらの胸か（両方／左のみ／右のみ） |
| ミルク・搾母乳 | ml を8段階（0〜7） |
| うんち | 量4段階・かたさ4段階と、それぞれ記録があったかどうか |
| 睡眠 | 長さを15分単位で |
| 搾乳・おしっこ・お風呂 | 時刻だけ |
| 曲の設定 | 日数、テンポ、音階 |

再生も同じ段階化した値を使うので、作った人と受け取った人には同じ曲が鳴ります。

### ヘッダ（両形式共通、3バイト）

| バイト | 内容 |
|---|---|
| 0 | 日数 − 1（1〜256日） |
| 1 | テンポ × 2（1日6秒なら 12） |
| 2 | 音階（0 ペンタトニック、1 琉球、2 都節、3 リディアン） |

## 旧形式 v1：1件ずつ3バイト

記録を時刻順に並べ、1件を3バイト（睡眠は4バイト）に詰めます。

```
バイト0: 日（0〜255）
バイト1: スロット(7ビット) | 種類の上位1ビット
バイト2: 種類の下位2ビット | 値(4ビット) | 補助(2ビット)
バイト3: 睡眠の長さ（15分単位）    ※睡眠のみ
```

種類は `母乳 0, ミルク 1, 搾母乳 2, 搾乳 3, おしっこ 4, うんち 5, お風呂 6, 睡眠 7` の3ビットです。値は授乳の段階かうんちの量・かたさ、補助は母乳の左右か、うんちの「記録あり」の印です。

単純で読みやすい反面、どの記録にも「日」と「種類」が丸ごと入ります。時刻もばらばらに並ぶので、圧縮があまり効きません。

## 新形式 v2：種類ごとにまとめて差分で書く

種類ごとに記録を集め、時刻は「前の記録から何スロット後か」で書きます。

```
ヘッダ（3バイト）
母乳:     件数 | 間隔, 間隔, … | 値, 値, …
ミルク:   件数 | 間隔, 間隔, … | 値, 値, …
搾母乳:   件数 | 間隔, … | 値, …
搾乳:     件数 | 間隔, …
おしっこ: 件数 | 間隔, …
うんち:   件数 | 間隔, … | 値, …
お風呂:   件数 | 間隔, …
睡眠:     件数 | 間隔, … | 長さ, …
```

- 時刻は、日とスロットをまとめた通し番号（日 × 96 + スロット）にします。最初の1件は0からの間隔です。
- 件数と間隔は可変長整数（varint）で書きます。127以下なら1バイトで、普段の間隔（授乳なら3時間おき＝12スロット前後）はほぼ1バイトに収まります。
- 値は1バイトです。母乳は `段階 | 左右 << 3`、うんちは `量 << 2 | かたさ`、記録ありの印を16と32のビットで持ちます。睡眠は長さを15分単位で入れます。

効く理由は、同じ種類の記録が似た間隔で繰り返すからです。「12, 11, 13, 12…」のような並びはdeflateがよく縮めますが、v1のように種類と時刻が混ざっていると、繰り返しが見えにくくなります。

### 例

1日分で、次の3件だけの記録を考えます（テンポ6秒、ペンタトニック）。

| 時刻 | 記録 | 段階化 |
|---|---|---|
| 01:00 | おしっこ | スロット4 |
| 01:15 | 母乳 左のみ 8分 | スロット5、段階2、左 |
| 03:00 | おしっこ | スロット12 |

**v1（12バイト）**

```
00 0C 00            ヘッダ：1日、テンポ6秒、ペンタトニック
00 09 00            01:00 おしっこ
00 0A 09            01:15 母乳 段階2 左
00 19 00            03:00 おしっこ
```

**v2（15バイト）**

```
00 0C 00            ヘッダ
01 05 0A            母乳: 1件、スロット5、値 = 段階2 | 左(1)<<3
00 00 00            ミルク・搾母乳・搾乳: 0件
02 04 08            おしっこ: 2件、スロット4、そこから8スロット後
00 00 00            うんち・お風呂・睡眠: 0件
```

この程度の記録だと、種類ごとの件数の分だけv2のほうが長くなります。記録が数百件になると間隔の繰り返しが効いてきて、圧縮後はv2のほうがずっと短くなります。

## 実際の長さ

実データ（4か月分）から作ったリンクの文字数です。

| 期間 | v1 | v2 |
|---|---|---|
| 7日 | 約560 | 374 |
| 28日 | 約2,700 | 1,270 |
| 31日 | 約3,000 | 1,402 |

v1の欄は形式を比較したときの測定値です。v2の欄とは記録のない端の日の扱いが違うので、目安として見てください。

## さらに短くするには

| 方法 | 見込み | 代償 |
|---|---|---|
| deflate をやめて、記録の傾向に合わせた算術符号化を自作する | 1割程度 | 実装と検証の手間が大きい |
| 時刻を30分単位にする | 1〜2割程度（推定） | 曲のリズムが粗くなる |
| 授乳などの段階を減らす | 少し | 音程の幅が狭くなる |
| おしっこなど一部の種類を入れない | 種類による | 受け取った人に、その楽器が鳴らない |
| 期間を短くする | 日数にほぼ比例 | なし（今すぐできる） |

サーバなしでURLにすべてを入れる方式では、1か月分で1,000文字前後が実用上の下限に近いと見ています。それより短くするには、情報を減らすか、サーバに保存して短いIDだけを渡すしかありません。後者は「サーバに送らない」という前提に反するので採っていません。
